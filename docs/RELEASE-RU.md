# Контрольный список релиза

Релиз — это версия `oh-my-cli` с тегом, опубликованная из `main`. Используйте этот
контрольный список, чтобы подтвердить поддерживаемые платформы, проверить артефакты
и сохранить доказательства отката перед публикацией. Команды здесь являются
процедурами оператора, выполняемыми сопровождающим; автоматизированная проверка
команд первого запуска находится в проверке дыма релиза (`npm run smoke`)
и охватывает [`docs/FIRST-RUN.md`](FIRST-RUN.md).

## Поддерживаемые платформы

Записываются, чтобы релиз выпускался только там, где он фактически протестирован.

- **Node.js:** `>= 22` (см. `engines.node` в `package.json`).
- **Операционные системы:** Linux, macOS и Windows — тот же набор, который
  `--doctor` сообщает как поддерживаемый. CI работает на Linux; macOS/Windows
  проверяются через кроссплатформенные фикстуры `--doctor`.

## Предрелизная проверка

Запустите стандартное подмножество релиза и подтвердите, что каждый шаг зеленый:

```bash
npm ci
npm run typecheck
npm run build
npm test
npm run test:integration
npm run smoke
```

`npm run smoke` включает проверку документации первого запуска, которая
завершается неудачей, если какая-либо команда, документированная в
`docs/FIRST-RUN.md`, использует устаревший синтаксис.

## Проверка артефактов

- Сборка производит бинарную входную точку `dist/index.js`. Подтвердите, что она разрешается:

  ```bash
  node dist/index.js --version
  ```

- Просмотрите точно то, что будет отправлено при публикации (в `package.json`
  нет allowlist `files`, поэтому проверьте список и подтвердите, что нет секретов,
  `.env` или локального состояния):

  ```bash
  npm pack --dry-run
  ```

- Подтвердите, что версия в `package.json` соответствует целевому тегу релиза.

## Доказательства отката

Релизы — это merge коммиты на `main`, поэтому релиз можно откатить без
потери истории. Ведите запись каждого релиза, чтобы откат был однозначным.

- **Откат merge коммита релиза** (сохраняет историю):

  ```bash
  git revert -m 1 <merge-commit-sha>
  ```

- **Перепубликуйте предыдущую известную-хорошую версию**, если опубликованный
  артефакт плохой, и перетегируйте только после проверки отката.

Записывайте следующее для каждого релиза (и для любого отката):

| Поле | Значение |
|---|---|
| Версия | |
| SHA merge коммита релиза | |
| Предыдущая известная-хорошая версия | |
| Вывод `node dist/index.js --version` | |
| Проверочный запуск (все зеленые?) | |
| Откат? (SHA + причина) | |

## Процесс релиза

### Подготовка
1. Обновите версию в `package.json`
2. Обновите CHANGELOG.md (если применимо)
3. Запустите предрелизную проверку

### Создание релиза
1. Создайте и протолкните тег:
   ```bash
   git tag vX.Y.Z
   git push origin vX.Y.Z
   ```
2. Создайте релиз на GitHub
3. Опубликуйте в npm (если применимо)

### Пострелизная проверка
1. Проверьте установку из npm:
   ```bash
   npm install -g oh-my-cli@X.Y.Z
   oh-my-cli --version
   ```
2. Запустите проверку дыма на свежей установке
3. Убедитесь, что документация актуальна

## Автоматизация

### CI/CD конвейер
- Тесты запускаются автоматически при push в `main`
- Проверка типов и линтинг выполняются при каждом коммите
- Интеграционные тесты запускаются для основных изменений

### Проверка дыма
Контрольный список проверки дыма включает:
- [ ] Установка и сборка работают
- [ ] CLI возвращает версию
- [ ] `--doctor` проходит все проверки
- [ ] `--preflight` подключается к провайдеру
- [ ] Команды из FIRST-RUN.md работают
- [ ] Все тесты проходят

## Устранение неполадок

### Если проверка дыма не проходит
1. Проверьте логи сборки
2. Убедитесь, что зависимости актуальны
3. Проверьте совместимость Node.js версии
4. Проверьте конфигурацию провайдера

### Если релиз содержит ошибку
1. Немедленно остановите развертывание
2. Задокументируйте проблему
3. Выполните откат по процедуре выше
4. Сообщите пользователям об откате

## Ответственность

Релизы выполняются только сопровождающими с доступом к:
- GitHub репозиторию
- npm аккаунту (если публикация в npm)
- Ключам подписи (если применимо)

Каждый релиз должен быть задокументирован и проверен минимум одним
другим сопровождающим перед публикацией.
