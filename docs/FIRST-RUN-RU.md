# Руководство по первому запуску

Это руководство проведет вас от свежего checkout до первой успешной задачи
и покажет, как проверить установку, прежде чем доверять ей. Каждая команда
`oh-my-cli` ниже выполняется проверкой дыма релиза, поэтому документированный
синтаксис остается актуальным.

## 1. Установка

Требуется **Node.js 22 или новее**. Из корня репозитория:

```bash
npm install
npm run build
npm link
```

`npm run build` компилирует исходники TypeScript в `dist/`; входная точка CLI —
`dist/index.js`. `npm link` помещает команду `oh-my-cli` на ваш PATH,
чтобы команды ниже работали как написано (`npm unlink -g oh-my-cli`
удаляет ее позже); без связывания запускайте те же команды как
`node dist/index.js ...`. Если вы видите ошибки компилятора, сборка сломана —
остановитесь здесь и исправьте их перед продолжением.

## 2. Настройка провайдера

`oh-my-cli` общается с OpenAI-совместимым эндпоинтом. Установите эти
переменные окружения (никогда не коммитьте реальные ключи — используйте
заполнители в документах и скриптах):

| Переменная | Обязательно | По умолчанию | Описание |
|---|---|---|---|
| `OPENAI_API_KEY` | Да | — | API-ключ для провайдера |
| `OPENAI_BASE_URL` | Нет | `https://api.openai.com/v1` | OpenAI-совместимый базовый URL |
| `OPENAI_MODEL` | Да | — | Имя модели для использования |

```bash
export OPENAI_API_KEY="ваш-ключ-api-здесь"
export OPENAI_MODEL="gpt-4o"
```

Альтернативно, сохраните некритичную конфигурацию модели в пользовательском файле
`~/.oh-my-cli/settings.json`, чтобы вам не приходилось экспортировать переменные
в каждой оболочке. Храните только имя модели, совместимый базовый URL и *имя*
переменной окружения, которая содержит учетные данные — никогда сам ключ:

```json
{
  "model": {
    "baseUrl": "https://dashscope.aliyuncs.com/compatible-mode/v1",
    "name": "qwen-latest-series-invite-beta-v77",
    "apiKeyEnv": "DASHSCOPE_API_KEY"
  }
}
```

Переменные окружения всегда имеют приоритет над файлом настроек, и файл настроек
читается только из пользовательского значения по умолчанию или явного
`--settings <path>` — никогда не обнаруживается автоматически внутри проекта.
См. [../README.md](../README.md#configuration) для полной таблицы приоритетов.

Третий вариант хранит учетные данные в проектно-локальном файле `.env`
в корне рабочей области (`OPENAI_API_KEY=...`, `OPENAI_BASE_URL=...`,
`OPENAI_MODEL=...`). Это контролируется доверием папки: только рабочая область,
доверенная с `--trust-workspace` (или `--trust` для одного запуска),
имеет свой `.env` прочитанным, и реальные переменные окружения всегда
побеждают значения `.env`. Файл питает только разрешение конфигурации модели —
он никогда не мутирует окружение процесса, поэтому его значения не наследуются
запущенными инструментами.

Секреты исключены из вывода: CLI скрывает токены, похожие на ключи, перед печатью.

## 3. Проверьте вашу настройку

Подтвердите, что среда выполнения и установка здоровы, перед запуском реальной задачи:

```bash
oh-my-cli --version
oh-my-cli --doctor
```

`--doctor` доступен только для чтения и проверяет версию Node runtime,
присутствие входной точки CLI, доступность записи в директорию состояния
(или возможность создания), и поддержку платформы. Каждая проверка помечается
`✓` проход, `⚠` предупреждение или `✗` сбой с исправлением; команда выходит
`0` только когда нет сбоев.

Чтобы отдельно подтвердить подключение к провайдеру (это делает сетевой вызов):

```bash
oh-my-cli --preflight
```

## 4. Запустите вашу первую задачу

Одиночный неинтерактивный запрос:

```bash
oh-my-cli -p "Перечисли файлы в этой директории"
```

Инструменты только для чтения никогда не требуют подтверждения. Мутирующие
инструменты следуют активному режиму подтверждения (см. ниже). Для автоматизации
и CI добавьте `--output json`, чтобы получить структурированные события вместо
текста.

Инструменты, изменяющие файлы или выполняющие команды оболочки, требуют
подтверждения, если вы не используете `--approval-mode yolo`. Режимы:

| Режим | Поведение |
|---|---|
| `default` (по умолчанию) | Подтверждайте каждый инструмент записи файлов или командной оболочки вручную |
| `auto-edit` | Автоматически подтверждайте редактирование файлов, но подтверждайте команды оболочки |
| `yolo` | Автоматически подтверждайте все (только для доверенных сред) |

Вы можете переключать режимы во время выполнения с `/mode`, например `/mode auto-edit`.

Для реальной работы, особенно с новыми зависимостями или структурой, начните с
подтверждения по умолчанию и переключитесь на `auto-edit` после того, как
увидите, что инструменты работают как ожидалось.

В интерактивном режиме нажмите **Enter** в пустом композиторе для выхода.

## 5. Работа с изображениями

Прикрепите файлы изображений (PNG, JPEG, GIF, WebP) для а��ализа с поддержкой зрения:

```bash
oh-my-cli -p "Опиши это изображение" --image screenshot.png

# Несколько изображений
oh-my-cli -p "Сравни эти диаграммы" --image diagram1.png diagram2.png
```

В интерактивном режиме используйте `/attach screenshot.png` для прикрепления
изображения к следующему запросу.

## 6. Продолжение сессий

Сессии сохраняются и могут быть возобновлены по ID или пользовательскому имени:

```bash
# Интерактивная сессия (указывайте имя для простоты повторного использования)
oh-my-cli --session-name "мой-рефакторинг"

# Позже, возобновление по имени
oh-my-cli --resume "мой-рефакторинг"

# Или поиск и выбор из списка
oh-my-cli --browse-sessions
```

Сессия, созданная без явного имени, получает уникальный ID; используйте
`--list-sessions`, чтобы найти ее.

## 7. Безопасность и доверие

По умолчанию `oh-my-cli` не доверяет рабочей области. Рабочая область должна быть
явно доверена, чтобы разрешить чтение `.env` или выполнение кода:

```bash
# Однократное доверие на этот запуск
oh-my-cli --trust -p "Задача"

# Постоянное доверие (записывает .trusted)
oh-my-cli --trust-workspace -p "Задача"
```

Подтверждение необходимо для любого инструмента, который:
- записывает файл
- запускает команду оболочки
- читает файл `.env` (если рабочая область не доверена)

## 8. Выход из строя и отладка

Если инструмент зависает, нажмите **Ctrl+C** для отмены. Для принудительной отмены
долгого или заблокированного запуска:

```bash
# Найдите идентификатор сессии
oh-my-cli --list-sessions

# Или если вы знаете идентификатор сессии, принудительно завершите
# (требует разработки — смотрите документацию по отладке)
```

Запуск с `--output json` предоставляет структурированные события, включая
статус инструмента и завершение, что полезно для отладки сценариев.
