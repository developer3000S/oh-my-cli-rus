# Русское руководство по быстрому старту

Это руководство является точкой входа для русскоязычных пользователей oh-my-cli,
охватывая установку, настройку модели (DashScope / OpenAI-совместимые эндпоинты),
запуск CLI и Desktop, безопасность сессий и файловые границы, а также
распространенные методы устранения неполадок. Английская документация является
авторитетной версией; в случае несоответствий между этой и английской версией
приоритет имеет английская версия:

- [README.md](../README.md) — полные функции и все опции командной строки
- [docs/FIRST-RUN.md](FIRST-RUN.md) — путь проверки от установки до первой задачи
- [SECURITY.md](../SECURITY.md) — политика безопасности
- [CONTRIBUTING.md](../CONTRIBUTING.md) — политика вклада

## Что это такое

oh-my-cli — это небольшой CLI с интеллектуальным агентом для работы с кодом,
предоставляющий инструменты для работы с файлами и командной оболочкой.
Он построен на Node.js 22, TypeScript и ESM. Его можно использовать как в
интерактивном терминале, так и для неинтерактивной автоматизации.
Также доступна локальная версия Desktop (Electron), предоставляющая графический
интерфейс на той же системе сессий.

## Установка

Требуется **Node.js 22 или выше**. В корне репозитория выполните:

```bash
npm install
npm run build
```

`npm run build` компилирует исходный код TypeScript в `dist/`, CLI вход —
`dist/index.js`. Можно запускать напрямую:

```bash
node dist/index.js --version
```

Или выполните `npm link`, после чего можно использовать команду `oh-my-cli`:

```bash
npm link
oh-my-cli --version
```

## Настройка модели (DashScope / OpenAI-совместимые эндпоинты)

oh-my-cli общается с OpenAI-совместимыми эндпоинтами. Алибаба Cloud DashScope
предоставляет OpenAI-совместимый режим, поэтому можно напрямую подключиться.
Есть два способа конфигурации, переменные окружения всегда имеют приоритет
над файлом конфигурации.

### Способ 1: Переменные окружения

| Переменная | Обязательно | По умолчанию | Описание |
|---|---|---|---|
| `OPENAI_API_KEY` | Да¹ | — | API Key провайдера |
| `OPENAI_BASE_URL` | Нет | `https://api.openai.com/v1` | OpenAI-совместимый базовый URL |
| `OPENAI_MODEL` | Да | — | Имя модели для использования |

```bash
export OPENAI_API_KEY="ваш-api-ключ"
export OPENAI_MODEL="qwen-latest"
```

¹ Для DashScope используйте переменную `DASHSCOPE_API_KEY` и установите
`OPENAI_BASE_URL="https://dashscope.aliyuncs.com/compatible-mode/v1"`.

### Способ 2: Файл настроек

Сохраните конфигурацию (без секретов) в `~/.oh-my-cli/settings.json`:

```json
{
  "model": {
    "baseUrl": "https://dashscope.aliyuncs.com/compatible-mode/v1",
    "name": "qwen-latest",
    "apiKeyEnv": "DASHSCOPE_API_KEY"
  }
}
```

Файл настроек читается только из пользовательского расположения по умолчанию
или явного `--settings <путь>` — никогда не обнаруживается автоматически
внутри проекта. См. [Полная таблица приоритетов](../README.md#configuration).

### Способ 3: Файл `.env` (ограниченный)

Вы можете разместить учетные данные в файле `.env` в корне рабочей области
(`OPENAI_API_KEY=...`, `OPENAI_BASE_URL=...`, `OPENAI_MODEL=...`).
Это защищено доверием папки: только рабочая область, доверенная с
`--trust-workspace` (или `--trust` для одного запуска), имеет свой `.env`
прочитанным, и реальные переменные окружения всегда побеждают значения `.env`.

Файл `.env` питает только разрешение конфигурации модели — он никогда не
мутирует окружение процесса, поэтому его значения не наследуются запущенными
инструментами.

## Проверка вашей настройки

Перед запуском реальных задач убедитесь, что среда выполнения и установка здоровы:

```bash
oh-my-cli --version
oh-my-cli --doctor
```

`--doctor` доступен только для чтения и проверяет:
- Версия Node runtime
- CLI вход присутствует
- Директория состояния доступна для записи (или может быть создана)
- Платформа поддерживается

Каждая проверка помечена `✓` проход, `⚠` предупреждение или `✗` сбой с исправлением;
команда выходит с кодом `0` только когда нет сбоев.

Чтобы отдельно подтвердить подключение к провайдеру (это делает сетевой вызов):

```bash
oh-my-cli --preflight
```

## Ваша первая задача

Одиночный неинтерактивный запрос:

```bash
oh-my-cli -p "Перечисли файлы в текущей директории"
```

Инструменты только для чтения никогда не требуют подтверждения. Инструменты,
изменяющие файлы или выполняющие команды оболочки, требуют подтверждения,
если вы не используете `--approval-mode yolo`. Режимы:

| Режим | Поведение |
|---|---|
| `default` (по умолчанию) | Подтверждайте каждый инструмент записи файлов или командной оболочки вручную |
| `auto-edit` | Автоматически подтверждайте редактирование файлов, но подтверждайте команды оболочки |
| `yolo` | Автоматически подтверждайте все (только для доверенных сред) |

Для реальной работы, особенно с новыми зависимостями или структурой, начните с
подтверждения по умолчанию и переключитесь на `auto-edit` после того, как
увидите, что инструменты работают как ожидалось.

## Работа с изображениями

Прикрепите файлы изображений (PNG, JPEG, GIF, WebP) для анализа с поддержкой зрения:

```bash
oh-my-cli -p "Опиши это изображение" --image screenshot.png

# Несколько изображений
oh-my-cli -p "Сравни эти диаграммы" --image diagram1.png diagram2.png
```

В интерактивном режиме используйте `/attach screenshot.png` для прикрепления
изображения к следующему запросу.

## Сессии и продолжение

Сессии сохраняются и могут быть возобновлены по ID или пользовательскому имени:

```bash
# Интерактивная сессия (укажите имя для простоты повторного использования)
oh-my-cli --session-name "мой-рефакторинг"

# Позже, возобновление по имени
oh-my-cli --resume "мой-рефакторинг"

# Или поиск и выбор из списка
oh-my-cli --browse-sessions
```

Сессия, созданная без явного имени, получает уникальный ID; используйте
`--list-sessions`, чтобы найти ее.

## Безопасность и доверие рабочей области

По умолчанию `oh-my-cli` не доверяет рабочей области. Рабочая область должна быть
явно доверена, чтобы разрешить чтение `.env` или выполнение кода:

```bash
# Однократное доверие на этот запуск
oh-my-cli --trust -p "Задача"

# Постоянное доверие (записывает .trusted)
oh-my-cli --trust-workspace -p "Задача"
```

Подтверждение необходимо для любого инструмента, который:
- записывает файл
- запускает команду оболочки
- читает файл `.env` (если рабочая область не доверена)

## CLI и Desktop

### CLI режим
```bash
# Интерактивный режим (ожидает ввода в терминале)
oh-my-cli

# Однократный запрос
oh-my-cli -p "Ваш запрос здесь"

# С указанием рабочей области
oh-my-cli --workspace ./ваш-проект -p "Помоги с рефакторингом"
```

### Desktop режим
```bash
# Запуск Desktop-версии
npm run desktop
```

Desktop-версия предоставляет графический интерфейс с теми же функциями,
что и CLI, включая управление сессиями, историю и инструменты.

## Распространенные проблемы и решения

### Ошибка "Missing API key"
Убедитесь, что переменная окружения `OPENAI_API_KEY` (или `DASHSCOPE_API_KEY`)
установлена и экспортирована.

### Ошибка "Workspace not trusted"
Доверьте рабочую область с `--trust-workspace` или `--trust`.

### Ошибка "Command requires approval"
Используйте режим `auto-edit` или `yolo`, или подтвердите действие вручную.

### Ошибка "Model not found"
Проверьте имя модели и базовый URL в настройках.
