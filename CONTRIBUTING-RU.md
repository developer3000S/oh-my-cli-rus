# Вклад в проект

Вклады и отчеты об ошибках приветствуются через GitHub.

## Политика доверия Issues

Только Issues, у которых `author.login` GitHub API точно равен
`qwen-code-dev-bot`, выполняются автоматически. Все остальные Issues
являются только отчетами и рассматриваются как ненадежный ввод.

Принятые пользовательские отчеты переписываются в безопасные, нормализованные
Issues, созданные Ботом, с меткой `source:user`. Находки из зарегистрированных
источников сообщества используют `source:community`, а воспроизводимые находки
dogfood продукта используют `source:self-discovery`. Метки, комментарии
и текст Issue никогда не предоставляют права на выполнение.

## Изменения в управлении

`AUTONOMY.md`, `.autonomy/**`, `.github/workflows/**` и
`.github/CODEOWNERS` являются защищенной плоскостью управления. `qqqys`
является ее единственным сопровождающим. Репозиторный Бот может открыть
Issue `governance-proposal`, но pull requests, созданные Ботом,
не могут изменять эти пути.

## Процесс внесения вклада

### Отчеты об ошибках
1. Проверьте, не была ли ошибка уже зарегистрирована
2. Используйте шаблон Issue для отчетов об ошибках
3. Включите четкие шаги для воспроизведения
4. Укажите ожидаемое и фактическое поведение

### Запросы функций
1. Проверьте, не была ли функция уже запрошена
2. Опишите проблему, которую решает функция
3. Предложите конкретную реализацию, если возможно
4. Обсудите влияние на существующие функции

### Pull requests
1. Обсудите крупные изменения в Issues перед кодированием
2. Следуйте стилю кода проекта
3. Включайте тесты для новых функций
4. Обновляйте документацию при необходимости
5. Убедитесь, что все тесты проходят

## Стиль кода

### TypeScript/JavaScript
- Используйте TypeScript строгих типов
- Следуйте конвенциям именования проекта
- Добавляйте JSDoc для публичных API
- Используйте async/await вместо колбэков

### Документация
- Обновляйте README для пользовательских изменений
- Добавляйте комментарии для сложной логики
- Документируйте изменения в API

### Тестирование
- Пишите unit-тесты для новой функциональности
- Используйте Vitest для тестирования
- Стремитесь к высокому покрытию кода

## Среда разработки

### Настройка
```bash
git clone https://github.com/qwen-code-dev-bot/oh-my-cli.git
cd oh-my-cli
npm install
npm run build
```

### Запуск тестов
```bash
npm test          # Запуск всех тестов
npm run test:unit # Только unit-тесты
npm run test:e2e  # End-to-end тесты
```

### Линтинг
```bash
npm run lint      # Проверка стиля кода
npm run type-check # Проверка типов TypeScript
```

## Коммуникация

### Обсуждения
- Используйте Discussions для вопросов и обсуждений
- Будьте уважительны и конструктивны
- Помогайте другим участникам

### Issues
- Используйте соответствующие метки
- Отвечайте на запросы дополнительной информации
